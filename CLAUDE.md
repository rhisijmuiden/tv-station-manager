# TV Station Manager

Monorepo (pnpm workspaces, TypeScript, Node 24).

- `branding/`: house styles, one folder per brand (logo, tokens, BRAND.md); `branding/active-brand` picks the one apps are built with, imported as `@brand/...`. UI colours/fonts come only from the brand `tokens.css` (`--tvsm-*`); use `brandColor()` when code needs a hex.
- `packages/platform`: shared server (Fastify + node:sqlite): auth, mail (SMTP), backup/restore (FTP/FTPS/SCP/SMB/OneDrive, full + incremental; targets in `src/backup/targets/`, SMB via `smbclient`, OneDrive via Graph with device-code sign-in and rotating refresh token, docs `docs/backup-locations.md`, Graph mock `test/graph-mock.ts`), self-update from GitHub releases, system info.
- `packages/ui`: shared React UI (Tailwind 4, i18next EN/NL, left sidebar, Info dialog, system pages). Apps call `mountPlatformApp`.
- `apps/orchestrator`: enrolls and manages nodes (Debian 13 .deb). Also keeps the ATEM inventory (`server/atem.ts`, docs `docs/atem-inventory.md`): one atem-connection link per switcher, snapshot in `atem_switchers.snapshot`, writes input names and manual switches (`POST /api/atem/:id/switch`); front-panel drawing per model family in `web/atemLayout.ts` (pure, tested) + `web/AtemPanel.tsx`. Connection diagram (`docs/connection-diagram.md`): `server/diagram.ts` (devices with cards/ports, cables), `server/diagramlogic.ts` is pure and shared with the web UI (card presets, ATEM ports, cable rules, auto layout, tally trace), UI `web/Diagram.tsx` on React Flow (`@xyflow/react`), switching/lock panel `web/AtemControl.tsx`. Per-ATEM control mode `atem_switchers.control` (automation/locked) is read by management nodes from `GET /automation-api/v1/atem-control` with the token in settings `automation.token`. Teranex inventory (`docs/teranex.md`): `server/teranex.ts` is READ ONLY (raw TCP 9800 Teranex Ethernet Protocol, only sends `PING`; never add commands that change the device without the user's typed approval, it feeds the live encoder), pure parser `server/teranexlogic.ts`; on the diagram a Teranex is a `device` row with `ref_id = 'teranex:<id>'`, exposed as kind `teranex`. Kiloview encoders/decoders (`docs/kiloview.md`): `server/kiloview.ts` is READ ONLY too (HTTP login + a fixed allowlist of status GETs in `server/kiloviewlogic.ts`; reboot/reset are GETs on these boxes, never widen the list), monitoring layer `transport`, page `web/Kiloview.tsx`. HyperDeck support is parked (branch `parked/hyperdeck`, `docs/parked/hyperdeck.md`); its migration stays in `server/legacy.ts`. Monitoring page (`docs/monitoring.md`): `server/monitoring.ts` (`GET /api/monitoring` aggregates nodes/ATEMs/Teranex/core + `monitor_devices` probed every 15 s: Owncast `/api/status`, HTTP, TCP or manual, optionally linked to a node's agent), pure rules in `server/monitorlogic.ts`, UI `web/Monitoring.tsx` (block diagram with SVG lines). Orchestrator migrations are `[...NODE_MIGRATIONS, ...ATEM_MIGRATIONS, ...ATEM_CONTROL_MIGRATIONS, ...DIAGRAM_MIGRATIONS, ...HYPERDECK_MIGRATIONS, ...MONITOR_MIGRATIONS, ...TERANEX_MIGRATIONS]`, append-only. Its server bundle ships `atemSocketChild.cjs` like the management node. Monitoring page (`docs/monitoring.md`): items per signal-path layer from the pure `web/monitorView.ts` (tested), 2D overview in `web/Monitoring.tsx`, 3D room (CSS 3D, no WebGL) in `web/MonitoringRoom.tsx`.
- `apps/management`: the director. `server/timeline.ts` (pure schedule/block expansion, tested), `director.ts` (playout loop; a clip CasparCG answers 404 for is skipped after `SKIP_MISSING_MS` via the pure `skipEvent` in `timeline.ts`, re-applied after every compile), `remote.ts` (remote sources: stream keys checked by MediaMTX via `POST /ingest/auth`, ingest status polling, DeckLink routing), `outputs.ts` (stream output: CasparCG FFmpeg consumer publishes `program/out-<id>` to the studio's MediaMTX, one `ffmpeg -c copy` relay per destination on the management node; docs `docs/stream-output.md`), `drivers.ts` (ATEM via atem-connection, CasparCG via casparcg-connection; fakes in tests), `media.ts` (UNAS over smbclient + ffprobe).
- `studio/`: Windows studio node: CasparCG overlay template (logo, clock, up next, ticker, subtitles), `windows/start-casparcg.ps1` launcher, README. Installer: `packaging/windows/install-studio.ps1` (agent + CasparCG 2.4 + MediaMTX RTMP/SRT ingest as WinSW services, generated casparcg.config, firewall). The agent reports studio status (`apps/agent/src/studio.ts`, AMCP + MediaMTX API) when `%ProgramData%\TVSM\studio\studio.json` exists; Windows self-update runs `update-agent.ps1` as a one-off scheduled task.
- Simple planning (`docs/simple-planning.md`): editors' menu is Now on TV / Week planning / Blocks / Library (`web/main.tsx`; older clock/rundown/wizard tools under Setup → Advanced planning). `web/pages/WeekPlan.tsx` (route `/week`, hour grid, drag blocks = week slots with `clock_mode 'none'`, "Plan live" = manual schedule entry with a hidden live block; the old board is `/week/advanced`). Hour blocks begin with the channel's fixed start (graphics `hourStart.blockId`, `blocks.hour_start`, prepended in `entryLeaves` via `hourStartLeaves` in `server/timeline.ts`). Base layer per kind of content: graphics `layers`, pure `server/layers.ts`, applied in `Director.graphicsData`; UI `web/components/ChannelLayers.tsx` on the Channel & layers page (`/graphics`). Library tabs: `web/components/LibraryTabs.tsx`; nav items can list extra routes in `also`.
- Week schedule (`docs/week-schedule.md`): categories, hour clocks, week slots and per-date rundowns. `server/hourclock.ts` is pure (clock layout, windows, distribution, auto pick, station time zone); `server/weekplan.ts` publishes the next days into `schedule` rows with `origin = 'week'` (partial blocks via `skip_items`/`take_items`, EPG groups them by `occurrence`). Manual schedule entries win; week rows cannot be edited via `/api/schedule`. Rundown blocks are `blocks.hidden = 1`. Slots on several weekdays with the same settings form a series (`seriesKey`), edited as one via `/api/week/slots/:id/series`. The editor wizard "New hour programme" is `web/pages/NewHour.tsx` (route `/new-hour`; one block planned at several days and start times via `startMins`); the left menu is grouped Editorial (with the Media sources submenu) / On air / Setup in `web/main.tsx`. Drag and drop: `web/components/dnd.tsx` (native HTML5 DnD, payload kept in a module store) and `MediaBin.tsx` (`WithMediaBin` docks the library; pages with `data-wide-page` get a wider content area, inner layouts use container queries).
- Orchestrator lock (`server/orchestrator.ts`, settings `orchestrator.link`, token encrypted): polls the orchestrator's ATEM control modes; `DeviceHub` wraps every ATEM driver in `GuardedSwitcher`, which holds program/preview/cut/auto while the ATEM (matched by host) is locked and takes the last held program on release. Control-room routes answer 409 `atem_locked`. The same link (address + token, even with locks off) feeds the read-only Monitoring page (`web/pages/Monitoring.tsx` reuses the orchestrator's `MonitoringPage` with `readOnly`; orchestrator `GET /automation-api/v1/monitoring`, proxied at `/api/orchestrator-monitoring`; `web/styles.css` adds the orchestrator files as Tailwind sources and `main.tsx` merges the `orch` i18n keys).
- Two studio nodes (`docs/two-nodes.md`): `studio_nodes.role` playout/live/both. A live item whose remote source is on another output than the channel's playout is prerolled (`LIVE_PREROLL_MS`), the ATEM cuts to it only once CasparCG plays the stream (`remote.playingSince`, `LIVE_SETTLE_MS`), otherwise the playout node stays on air (standby, filler); the overlay is mirrored on the live output.
- Beeldkrant (`docs/beeldkrant.md`): RSS feeds (`rss_feeds`/`rss_items`; WordPress REST with featured images, RSS fallback, or any RSS/Atom feed) and beeldkranten (`beeldkranten`, `beeldkrant_feeds`, settings JSON = `beeldkrantSchema`). `server/rsslogic.ts` is pure (parsing, `htmlToText`, `truncate`, `buildPages`); `server/rss.ts` fetches and serves `/beeldkrant/page.html` (CasparCG HTML producer, `server/beeldkrant-page.ts`), `/beeldkrant/<id>/data.json` and cached pictures `/beeldkrant/img/<item>`. Block items of type `beeldkrant` become timeline leaves the director plays with `playHtml` on the playout layer; their default length comes from `beeldkrantRef` (`server/beeldkrantdb.ts`). "Rest of the hour": `blocks.fill` (`beeldkrant:<id>`/`webcam:<id>`, NULL = channel filler) makes `compile()` emit `fill: true` events from the end of the block's material until the next whole hour or next entry (occurrence entries share it, `blockFill` follows a rundown's first child block).
- Regional info (`docs/regional-info.md`): traffic (NDW DATEX II, VILD points in `server/vildpoints.ts`), events (iCal/RSS + manual list), council meetings (iBabs/Notubiz/iCal) and P2000 (alarmeringen.nl region RSS) as `rss_feeds` rows with `source` + `config` JSON (one feed per source). `server/regionallogic.ts` is pure (schemas, parsers, item texts, P2000 privacy filter), `server/regional.ts` loads and serves `/api/regional/*`. `rss_items.rank` fixes the order, `hold` ('pending'/'rejected') and `show_from` (delay) keep items off air (filtered in `beeldkrantdb.ts`/`tickerdb.ts`), `note` is editor-only. UI `web/components/RegionalInfo.tsx`, tab Beeldkranten > Regionaal.
- Webcams & streams (`docs/webcams.md`): table `webcams` (kind hls/rtsp/rtmp/srt/video/mjpeg/image/page, settings JSON = `webcamSettingsSchema`), block item type `webcam` (`block_items.webcam_id`); every webcam gets its own one-item block (dragged from the library tab Webcams). `server/webcamlogic.ts` is pure (`detectKind`, `scanPage` finds streams in a webcam web page, ffmpeg args, `playPlan`); `server/webcams.ts` (inspect, test with ffmpeg frame grab, 10-min checks with thumbnails in `<dataDir>/webcams`, relay `/webcam/<id>/live.ts` = `ffmpeg -c copy` to MPEG-TS for CasparCG, `/webcam/page.html` for pictures/MJPEG/caption/offline card). The director plays it on layer 10, caption on `CAPTION_LAYER` 11, offline card + retry when PLAY fails. URL credentials are masked as `***` in the API.
- Recordings (`docs/recordings.md`): `server/recordlogic.ts` is pure (settings, `decide` start/stop per poll, file names, ffmpeg args, `repeatTimes`); `server/recorder.ts` runs after every ingest poll, records each online remote source on the management node with `ffmpeg -c copy` into MPEG-TS pieces (`<dataDir>/recordings`), joins them into an MP4, trims with `-ss/-t -c copy`, copies into the library (`putIntoSource` in `media.ts`, upserts the `media` row) and plans repeats as manual schedule entries with a block per recording. Per-source settings in `live_sources.recording` (JSON, `sourceRecordingSchema`), global ones in settings key `recordings`.
- Dashboard "Now on TV" (`web/components/NowOnTv.tsx`): `/api/control` returns per channel `program` (the hour block on air: all schedule entries of the same week-schedule occurrence, from the pure `programAt` in `server/timeline.ts`, with `index` of the current item and the `next` programme). Stream preview per channel (Owncast `/embed/video` page in an iframe, `.m3u8`/`.mp4` in a video element): settings key `dashboard.previews`, `server/preview.ts` (`/api/dashboard/previews`, suggests `http://<rtmp host>:8080/embed/video` from a channel stream output to an own RTMP server).
- Switch buttons (`docs/switching.md`): `server/switching.ts` (table `switch_buttons`: channel, name, colour, live source), editors' page `web/pages/Switch.tsx` (`/switch`, admin page `/switch-buttons`). Pressing = `Director.takeLive` (manual override; `Director.resume` ends it, `overrideEnded` listeners); for a stream the editor's record/repeat choice goes to `Recorder.goLive` (overrides the source setting, stored in `recordings.plan`), `Recorder.liveEnded` stops it with reason `live_end`.
- Audio under the broadcast (`docs/audio.md`): `audio_sources` (stream / soundcard via dshow / decklink), `server/audio.ts`. `blocks.audio` and `block_items.audio` are TEXT: NULL = follow parent, `'none'`, `'<id>'`; beeldkrant setting `audioSourceId` is the default for beeldkrant items. Resolved in `expandBlock` into `Leaf.audioSourceId` (item > block > parent block > beeldkrant). The director's `syncAudio` plays it on CasparCG layer 5 (`AUDIO_LAYER`, opacity 0) via the optional driver methods `playAudio`/`volume`; only for media/beeldkrant events.
- Newest clips (`docs/newest-clips.md`): block item type `auto` with a rule in `block_items.auto_rule` (category or folder, count, max age/minutes, order; `server/autofill.ts`, pure `pickClips`). The loader's `autoMedia(rule, asOf)` returns the clips; `expandBlock`/`entryLeaves` pass the entry start as `asOf` so a block on air does not change. Shared item writer `writeBlockItems` + `ITEM_COLUMNS` in `content.ts` (blocks page and week rundowns). Rule `pick` = newest / rotate / random: rotate and random picks per broadcast (`occ:<occurrence>` or `entry:<id>`) and item path are remembered in `auto_picks` within 3 h of air (`media.last_pick_at`), no clip twice per broadcast (`PickMemory` per loader). Used for hour blocks built from folders (ad, bumper, item, bumper), also in the New hour wizard.
- Coming up slide (`docs/lineup.md`): block item type `lineup` (only `duration_ms`, default `DEFAULT_LINEUP_MS` 15 s); settings per channel in `graphics.lineup` (`lineupSchema`). `server/lineuplogic.ts` is pure (`lineupRows`: programme clips + live items starting after the slide within `minutesAhead`; `lineupHtml`: static 1920x1080 page in the station time zone); `server/lineup.ts` serves `/lineup/page.html?channel=&at=` (public; `preview=1`, `settings=` for the Graphics page iframe). The director plays it with `playHtml` on the playout layer and hides the overlay.
- Phone layout (`docs/mobile.md`): `packages/ui/src/mobile.ts` (`useMobile`, view choice in localStorage `tvsm.view`), `AppShell` bottom bar from nav items with `mobile: true`, `Dialog` as bottom sheet; touch drag polyfill `apps/management/web/components/touchDrag.ts` (long press -> synthetic HTML5 drag events).
- Menu: `NavItem.children` makes a folding submenu in `packages/ui` `AppShell` (opens by itself on its pages; groups fold too, state in localStorage `tvsm.nav.folded`). Management media sources are one submenu.
- News ticker (`docs/ticker.md`): channel `graphics.ticker` (`tickerSchema`, source text/rss/both, feeds of the beeldkrant, speed px/s, font size, colours, label, separator, refresh). `server/tickerlogic.ts` is pure (headlines, items, `tickerHeight`, `tickerData`), `server/tickerdb.ts` reads `rss_items`; the director caches headlines per channel for `refreshMinutes` and plays a beeldkrant with `&ticker=<px>` when the ticker stays on air over it. Overlay scrolls a queue of pieces (no jump on new headlines). Preview `POST /api/ticker/preview`, UI `web/components/TickerCard.tsx`.
- Info pages (`docs/info-pages.md`): table `info_pages` (settings JSON = `infoPageSchema`, picture in `<dataDir>/infopages`), block item type `info` (`block_items.info_page_id`), default length on the page (`infoPageRef` in `server/infopagedb.ts`). `server/infopagelogic.ts` is pure (text blocks, layouts, HTML in the channel's coming-up slide colours); `server/infopages.ts` (API, `/infopage/page.html?id=&channel=`, `/infopage/img/<id>`); every page has its own one-item block (genre `info`, hidden in the Blocks list); layer kind `info`. UI `web/pages/InfoPages.tsx` under Setup > Sources, library tab Info.
- ATEM ports (`docs/atem-ports.md`): inputs are labelled by connector ("SDI in 8 · CASPARCG01") from the ATEM's own `externalPortType`; pure `server/atemports.ts` (tested), web `web/atemPorts.tsx` (`portLabel`, `PortOptions`, `useChannelInputs`); last known inputs cached in `atem_devices.inputs` for offline ATEMs.
- Subtitles: `.srt`/`.vtt` next to a clip (`apps/management/server/subtitles.ts`), served at `/graphics/subtitles/:mediaId`.
- SSO: `packages/platform/src/sso.ts` (Microsoft Entra ID via openid-client, settings key `sso`, routes `/api/auth/sso/*` and `/api/settings/sso`). Users have `auth_provider` (`local`/`entra`) and `external_id` (`<tid>:<oid>`); Entra users have password_hash `!`. Tests use a mock provider via `TVSM_SSO_AUTHORITY`. Docs: `docs/sso.md`.
- Roles: `admin` > `editor` (editor-in-chief) > `operator`. Use `requireRole(req, ...)` from `@tvsm/platform` on write routes.
- Agent self-update + provisioning (`docs/agent-provisioning.md`): heartbeat `update.latest`/`update.auto` (settings key `agents`, per node `nodes.auto_update`), agent `src/autoupdate.ts`; `update-agent.ps1` rolls back when `health.json` does not appear. Orchestrator `server/provisionlogic.ts` is pure (plan, warnings, on-air via `atem_inputs.node_id`, typed-name confirm), routes `/api/nodes/:id/provision{,/plan}`; command `provision` is held until the agent reports capability `provision`; result status `running` fills `node_commands.progress`. Agent `src/provision.ts` starts `packaging/windows/provision.ps1` as scheduled task (status.json), `src/inventory.ts` runs `inventory.ps1`. Orchestrator migrations end with `...PROVISION_MIGRATIONS, ...KILOVIEW_MIGRATIONS`. UI `web/Provision.tsx`.
- Editor guide (`docs/help.md`): static Dutch guide with screenshots/videos in `apps/management/web/public/help/` (served at `/help/index.html`); sidebar Help link via `mountPlatformApp({ helpUrl })` (`nav.help`).
- `packaging/`: .deb builder (bundles Node), systemd unit, update helper, `install.sh`.

Rules:
- Every user-facing string goes through i18n with both `en` and `nl` keys.
- Admin UIs keep the menu on the left and the Info button (version, check/install updates) in the sidebar.
- Every feature PR adds a changelog file `changelog/<package.json version>/<feature>.json` (EN + NL, kinds added/changed/improved/fixed/removed; shown under Info > What's new, used as release notes; see `CONTRIBUTING.md`, `docs/changelog.md`) and, when editors use it, extends the editor guide `apps/management/web/public/help/index.html`.
- On a production release: set `date` in `changelog/<version>/release.json`, then bump the version and create the next `changelog/<next>/release.json` without a date.
- Branches: feature branch -> PR into `test` -> merge `test` into `production`. Pushes to either publish a release (see `.github/workflows/release.yml`). Bump `package.json` version for a new production release.

Commands: `pnpm install`, `pnpm typecheck`, `pnpm test`, `pnpm dev:orchestrator` (API :8080, UI :5173), `pnpm dev:management` (API :8081, UI :5174).

The management server bundle stubs the native freetype2 add-on and ships `atemSocketChild.cjs` next to `server.mjs` (see `apps/management/build-server.mjs`).
