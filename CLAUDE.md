# TV Station Manager

Monorepo (pnpm workspaces, TypeScript, Node 24).

- `branding/`: house styles, one folder per brand (logo, tokens, BRAND.md); `branding/active-brand` picks the one apps are built with, imported as `@brand/...`. UI colours/fonts come only from the brand `tokens.css` (`--tvsm-*`); use `brandColor()` when code needs a hex.
- `packages/platform`: shared server (Fastify + node:sqlite): auth, mail (SMTP), backup/restore (FTP/FTPS/SCP, full + incremental), self-update from GitHub releases, system info.
- `packages/ui`: shared React UI (Tailwind 4, i18next EN/NL, left sidebar, Info dialog, system pages). Apps call `mountPlatformApp`.
- `apps/orchestrator`: enrolls and manages nodes (Debian 13 .deb). Also keeps the ATEM inventory (`server/atem.ts`, docs `docs/atem-inventory.md`): one atem-connection link per switcher, snapshot in `atem_switchers.snapshot`, writes input names and manual switches (`POST /api/atem/:id/switch`); front-panel drawing per model family in `web/atemLayout.ts` (pure, tested) + `web/AtemPanel.tsx`. Connection diagram (`docs/connection-diagram.md`): `server/diagram.ts` (devices with cards/ports, cables), `server/diagramlogic.ts` is pure and shared with the web UI (card presets, ATEM ports, cable rules, auto layout, tally trace), UI `web/Diagram.tsx` on React Flow (`@xyflow/react`), switching/lock panel `web/AtemControl.tsx`. Per-ATEM control mode `atem_switchers.control` (automation/locked) is read by management nodes from `GET /automation-api/v1/atem-control` with the token in settings `automation.token`. Orchestrator migrations are `[...NODE_MIGRATIONS, ...ATEM_MIGRATIONS, ...ATEM_CONTROL_MIGRATIONS, ...DIAGRAM_MIGRATIONS]`, append-only. Its server bundle ships `atemSocketChild.cjs` like the management node.
- `apps/management`: the director. `server/timeline.ts` (pure schedule/block expansion, tested), `director.ts` (playout loop), `remote.ts` (remote sources: stream keys checked by MediaMTX via `POST /ingest/auth`, ingest status polling, DeckLink routing), `outputs.ts` (stream output: CasparCG FFmpeg consumer publishes `program/out-<id>` to the studio's MediaMTX, one `ffmpeg -c copy` relay per destination on the management node; docs `docs/stream-output.md`), `drivers.ts` (ATEM via atem-connection, CasparCG via casparcg-connection; fakes in tests), `media.ts` (UNAS over smbclient + ffprobe).
- `studio/`: Windows studio node: CasparCG overlay template (logo, clock, up next, ticker, subtitles), `windows/start-casparcg.ps1` launcher, README. Installer: `packaging/windows/install-studio.ps1` (agent + CasparCG 2.4 + MediaMTX RTMP/SRT ingest as WinSW services, generated casparcg.config, firewall). The agent reports studio status (`apps/agent/src/studio.ts`, AMCP + MediaMTX API) when `%ProgramData%\TVSM\studio\studio.json` exists; Windows self-update runs `update-agent.ps1` as a one-off scheduled task.
- Week schedule (`docs/week-schedule.md`): categories, hour clocks, week slots and per-date rundowns. `server/hourclock.ts` is pure (clock layout, windows, distribution, auto pick, station time zone); `server/weekplan.ts` publishes the next days into `schedule` rows with `origin = 'week'` (partial blocks via `skip_items`/`take_items`, EPG groups them by `occurrence`). Manual schedule entries win; week rows cannot be edited via `/api/schedule`. Rundown blocks are `blocks.hidden = 1`. Slots on several weekdays with the same settings form a series (`seriesKey`), edited as one via `/api/week/slots/:id/series`. The editor wizard is `web/pages/NewHour.tsx` (route `/new-hour`); the left menu is grouped Editorial / On air / Setup in `web/main.tsx`. Drag and drop: `web/components/dnd.tsx` (native HTML5 DnD, payload kept in a module store) and `MediaBin.tsx` (`WithMediaBin` docks the library; pages with `data-wide-page` get a wider content area, inner layouts use container queries).
- Orchestrator lock (`server/orchestrator.ts`, settings `orchestrator.link`, token encrypted): polls the orchestrator's ATEM control modes; `DeviceHub` wraps every ATEM driver in `GuardedSwitcher`, which holds program/preview/cut/auto while the ATEM (matched by host) is locked and takes the last held program on release. Control-room routes answer 409 `atem_locked`.
- Two studio nodes (`docs/two-nodes.md`): `studio_nodes.role` playout/live/both. A live item whose remote source is on another output than the channel's playout is prerolled (`LIVE_PREROLL_MS`), the ATEM cuts to it only once CasparCG plays the stream (`remote.playingSince`, `LIVE_SETTLE_MS`), otherwise the playout node stays on air (standby, filler); the overlay is mirrored on the live output.
- Beeldkrant (`docs/beeldkrant.md`): RSS feeds (`rss_feeds`/`rss_items`; WordPress REST with featured images, RSS fallback, or any RSS/Atom feed) and beeldkranten (`beeldkranten`, `beeldkrant_feeds`, settings JSON = `beeldkrantSchema`). `server/rsslogic.ts` is pure (parsing, `htmlToText`, `truncate`, `buildPages`); `server/rss.ts` fetches and serves `/beeldkrant/page.html` (CasparCG HTML producer, `server/beeldkrant-page.ts`), `/beeldkrant/<id>/data.json` and cached pictures `/beeldkrant/img/<item>`. Block items of type `beeldkrant` become timeline leaves the director plays with `playHtml` on the playout layer; their default length comes from `beeldkrantRef` (`server/beeldkrantdb.ts`).
- Recordings (`docs/recordings.md`): `server/recordlogic.ts` is pure (settings, `decide` start/stop per poll, file names, ffmpeg args, `repeatTimes`); `server/recorder.ts` runs after every ingest poll, records each online remote source on the management node with `ffmpeg -c copy` into MPEG-TS pieces (`<dataDir>/recordings`), joins them into an MP4, trims with `-ss/-t -c copy`, copies into the library (`putIntoSource` in `media.ts`, upserts the `media` row) and plans repeats as manual schedule entries with a block per recording. Per-source settings in `live_sources.recording` (JSON, `sourceRecordingSchema`), global ones in settings key `recordings`.
- Subtitles: `.srt`/`.vtt` next to a clip (`apps/management/server/subtitles.ts`), served at `/graphics/subtitles/:mediaId`.
- SSO: `packages/platform/src/sso.ts` (Microsoft Entra ID via openid-client, settings key `sso`, routes `/api/auth/sso/*` and `/api/settings/sso`). Users have `auth_provider` (`local`/`entra`) and `external_id` (`<tid>:<oid>`); Entra users have password_hash `!`. Tests use a mock provider via `TVSM_SSO_AUTHORITY`. Docs: `docs/sso.md`.
- Roles: `admin` > `editor` (editor-in-chief) > `operator`. Use `requireRole(req, ...)` from `@tvsm/platform` on write routes.
- `packaging/`: .deb builder (bundles Node), systemd unit, update helper, `install.sh`.

Rules:
- Every user-facing string goes through i18n with both `en` and `nl` keys.
- Admin UIs keep the menu on the left and the Info button (version, check/install updates) in the sidebar.
- Branches: feature branch -> PR into `test` -> merge `test` into `production`. Pushes to either publish a release (see `.github/workflows/release.yml`). Bump `package.json` version for a new production release.

Commands: `pnpm install`, `pnpm typecheck`, `pnpm test`, `pnpm dev:orchestrator` (API :8080, UI :5173), `pnpm dev:management` (API :8081, UI :5174).

The management server bundle stubs the native freetype2 add-on and ships `atemSocketChild.cjs` next to `server.mjs` (see `apps/management/build-server.mjs`).
